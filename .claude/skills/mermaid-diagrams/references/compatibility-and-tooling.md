# Renderer compatibility, pitfalls, validation, and generation

## Renderers

| Renderer | Notes |
| --- | --- |
| **GitHub** (Markdown files, issues, PRs, wikis) | Renders natively in a sandboxed iframe. Its Mermaid version **lags upstream by one or more minor releases**; put `info` in a mermaid block to see which version it runs. `architecture-beta` icon packs (e.g. `azure:*`) don't render. Hard-coded fill colors become unreadable in dark mode. Corporate proxies that block `viewscreen.githubusercontent.com` show "Unable to render rich display". |
| **Azure DevOps** wiki / Markdown | Supports a fixed subset: sequence, Gantt, flowchart (written as `graph`), class, state, user journey, pie, requirement, gitGraph, ER, timeline. **No C4, no `architecture-beta`, no mindmap.** No HTML tags in labels, no Font Awesome, and no long arrows like `---->`. Accepts both `::: mermaid` blocks and code fences. |
| **DocFX** | Mermaid code blocks render only with the `modern` template, and only in the browser. PDF output leaves them out. |
| **VS Code / Rider previews** | Usually newer than GitHub. Something that renders in the IDE may still fail on GitHub. |

Lowest common denominator, which works everywhere above:

- `graph`/`flowchart`, `sequenceDiagram`, `classDiagram`, `stateDiagram-v2`, `erDiagram`
- classic node shapes: `[]`, `()`, `([])`, `[()]`, `{{}}`, `{}`
- quoted labels, `accTitle`, `accDescr`, `classDef` with stroke styles only

Avoid these when the targets differ or are unknown:

- the newer `A@{ shape: … }` syntax
- `architecture-beta`
- `C4*`
- `block-beta`
- HTML in labels
- front-matter themes

## Syntax pitfalls

| Symptom | Cause | Fix |
| --- | --- | --- |
| Parse error on a node | Label contains `()[]{}:;#` or starts with a special character | Quote it: `id["Orders API (v2)"]` |
| Flowchart breaks unexpectedly | A node named `end` (lowercase) | Rename it: `done`, `finish`, `End` |
| Edge renders as a circle or cross | A node ID starting with `o` or `x` right after `---` or `-->` | Add a space, or rename the ID |
| `;` or `#` truncates a sequence message | Both are special in messages | Use `#59;` for `;` and `#35;` for `#`, or rephrase |
| An ER attribute fails | A space in the type or name | Use `string DisplayName`, not `display name` |
| A generic type is lost in a class diagram | `<T>` is read as HTML | Use `List~T~` |
| Text unreadable in dark mode | `style`/`classDef` with `fill` or `color` | Drop the fills; use `stroke-width` or `stroke-dasharray` for emphasis |

## Validation

**Locally, or from an agent:**

```bash
# Renders every mermaid block in the file; exits non-zero on a parse error.
# The output directory must already exist.
out=$(mktemp -d)
npx -y @mermaid-js/mermaid-cli -i path/to/doc.md -o "$out/doc.md"
```

To validate many files, loop over `git ls-files '*.md' | xargs grep -l '```mermaid'`.

**In CI:** the `dotnet-repo-docs` skill has a docs workflow with a Mermaid job. On Linux
runners, mermaid-cli needs a Puppeteer config with `{"args": ["--no-sandbox"]}` passed via `-p`.

**Caveat.** mermaid-cli bundles a newer Mermaid than GitHub. Passing validation proves the syntax
is valid, not that GitHub can render it yet. For new syntax, check a rendered preview on GitHub
(the PR's "Files changed" rich diff), or stay within the lowest common denominator above.

## Generate rather than hand-draw

### EF Core → ER diagram (recommended wherever EF Core is used)

The `EfToMermaid` package (from Simon Cropp's DbToMermaid) renders an ER diagram from
`DbContext.Model`. Building the model doesn't need a database. This was checked with
EfToMermaid 2.1.1 and EF Core Sqlite on .NET 10.

```csharp
using DbToMermaid;
using Microsoft.EntityFrameworkCore;

public class DocsGeneration
{
    [Fact]
    [Trait("Category", "DocsGen")]
    public async Task DataModelDiagram()
    {
        // Model building only: no connection is opened. Use the same provider as production
        // so column types match (UseSqlServer("Server=unused") works the same way).
        var options = new DbContextOptionsBuilder<AppDbContext>()
            .UseSqlite("Data Source=:memory:")
            .Options;
        await using var context = new AppDbContext(options);

        var mermaid = await EfToMermaid.RenderMarkdown(context.Model); // includes the ```mermaid fence

        var path = Path.Combine(RepoRoot(), "docs", "data-model.md");
        await File.WriteAllTextAsync(path,
            "# Data model\n\n<!-- Generated by DocsGeneration.DataModelDiagram. Do not edit by hand. -->\n\n" + mermaid);
    }

    static string RepoRoot()
    {
        var dir = new DirectoryInfo(AppContext.BaseDirectory);
        // .git is a directory in a normal clone and a file in a git worktree.
        while (dir is not null && !Path.Exists(Path.Combine(dir.FullName, ".git")))
            dir = dir.Parent;
        return dir?.FullName ?? throw new InvalidOperationException("Repository root not found.");
    }
}
```

In CI, run the tests and then fail if the committed file is stale:

```bash
dotnet test --filter Category=DocsGen && git diff --exit-code -- docs/data-model.md
```

If the repo already uses Verify for snapshot tests, you can snapshot the Markdown instead, so
the schema diff shows up as a snapshot change.

Output notes:

- **Naming.** Entities are named after tables and relationships after FK constraint names.
- **Renderer.** It uses the ER entity-alias syntax (`Customers["**Customers**"]`). This renders on
  GitHub; check Azure DevOps before relying on it there.
- **Generated files.** Don't hand-edit one. Change the model and regenerate.

### Other generators

These were not tested for these skills; check each one's current status before adopting it.

| Source | Tool | Output |
| --- | --- | --- |
| SQL Server schema | `SqlServerToMermaid` / `SqlServerToMermaidTool` (same repo as EfToMermaid) | ER diagram |
| C# source (Roslyn) | `mcdg` dotnet tool and similar class-diagram generators | Class diagram. Use sparingly; see the SKILL guidance on code-level diagrams |
| Structurizr DSL workspace | `structurizr export -format mermaid` | C4 views. The exported diagrams need `securityLevel: loose`, which GitHub's sandbox may not allow, so prefer committed SVGs or PlantUML for Structurizr |
| .NET Aspire AppHost | No built-in export. A custom publish-time hook can walk the app model and write a flowchart | Container view |

**Rule of thumb.** Anything derived from a schema or model should be generated and checked in CI.
Anything that expresses **intent** should be hand-written and reviewed: context views,
container boundaries, and the important flows.
