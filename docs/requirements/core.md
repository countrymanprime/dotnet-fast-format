# Core requirements

Draft v0.1, 2026-10-01. Written in [EARS](https://alistairmavin.com/ears/)
form (sentence templates such as "When X, the formatter shall Y"). **No tests exist yet**, so every test anchor below is
planned; a requirement stays a draft until its anchor is a real, passing test.

Priority: Must / Should / Could. IDs are stable and never reused.

## Formatting (FMT)

| ID | Requirement | Priority | Scenario | Test anchor (planned) |
|---|---|---|---|---|
| FMT-001 | The formatter shall produce identical text when run on its own output. | Must | Format a file twice; compare. | `Invariants.Idempotent`, every fixture and corpus file (M0) |
| FMT-002 | The formatter shall produce output whose syntax tree equals the input's, ignoring trivia. | Must | Parse both; compare tokens. | `Invariants.TreePreserving` (M0) |
| FMT-003 | The formatter shall keep every comment and preprocessor directive, in order. | Must | Count and compare before and after. | `Invariants.NoLoss` (M0) |
| FMT-004 | If a file fails to parse, then the formatter shall leave it unchanged and report an error. | Must | Format a file with a syntax error. | `CliFormatTests.ParseErrorLeavesFileUntouched` (M1) |
| FMT-005 | The formatter shall produce output that parses with no new diagnostics. | Must | Parse output; compare diagnostics. | `Invariants.ValidOutput` (M0) |
| FMT-006 | The formatter shall not reflow the contents of regular, verbatim, interpolated or raw string literals. | Must | Fixtures for each literal kind, including multi-line ones as an argument and an initializer. | `tests/golden/strings/*` (M2) |
| FMT-007 | The formatter shall preserve a file's BOM and the line terminators it does not write itself, unless `.editorconfig` sets `charset` to `utf-8` or `utf-8-bom` (then the BOM is removed or added, CFG-009) or `end_of_line` (then see CFG-007). | Should | A BOM file and a CRLF file, with and without those keys. | `CliConfigTests.TheBomIsKeptWhenCharsetIsNotSet`, `CliConfigTests.CharsetUtf8RemovesTheBom`, `CliConfigTests.CharsetUtf8BomAddsTheBom` (M4; M1 already preserves both, see T-106) |
| FMT-008 | When a syntax node kind has no printer yet, the formatter shall emit that node's source text unchanged. | Must | A file mixing a supported declaration with an unsupported statement. | `Formatter.UnsupportedNodesAreVerbatim` (M1; [ADR 0008](../decisions/0008-print-unsupported-syntax-verbatim.md)) |
| FMT-009 | If a comment or preprocessor directive is in a position that [ADR 0010](../decisions/0010-keep-comments-at-node-boundaries.md) does not format (inside a header or parameter list, after a `{` on its line, several comments after one token, a comment followed by code on its line), then the formatter shall emit the text of the node that owns it unchanged, the trivia on its own tokens included. | Must | A member with a comment inside its parameter list, next to formatted siblings. | `Formatter.NodesWithCommentsInOtherPositionsAreVerbatim` (M3; replaces the M1 rule) |
| FMT-010 | Before writing a file, the formatter shall re-parse its output and, if the tokens, comments or directives differ from the input's or the output has new syntax errors, leave the file unchanged and exit 2. | Should | A deliberately broken formatter. | `CliFormatTests.SelfCheckBlocksBadOutput` (M1; [ADR 0009](../decisions/0009-self-check-output-before-writing.md)) |
| FMT-011 | When a file contains `#if`, `#elif`, `#else`, `#endif`, `#region` or `#endregion`, the formatter shall keep every directive and every line of disabled text in order, and shall format only the code the no-symbols parse contains ([ADR 0011](../decisions/0011-format-the-no-symbols-parse-and-keep-directives-as-lines.md)). | Must | `#if` around members, a `#if` that splits a header, nested `#if`. | `Formatter.ConditionalDirectivesAreKept` (M3; replaces the M1 whole-file rule) |
| FMT-012 | When a file contains nothing but whitespace, comments and directives, the formatter shall emit the whole file unchanged. | Must | An empty file and a comment-only file. | `Formatter.FilesWithoutDeclarationsAreVerbatim` (M1; narrowed in M3) |
| FMT-013 | If the formatter changes a file, then the output shall end with exactly one line terminator, or with none when `.editorconfig` sets `insert_final_newline = false` (CFG-008), and the line breaks the formatter writes shall use the input's dominant line terminator (LF unless CRLF is more common), or the one `end_of_line` names (CFG-007). An empty file stays empty. | Must | A CRLF file without a final newline; an LF file with three. | `Formatter.EndsWithExactlyOneNewlineInTheDominantLineEnding`, `Formatter.UsesTheDominantLineEnding` (M1), `FormatterOptionsTests.InsertFinalNewlineFalseEndsWithoutALineBreak` (M4) |
| FMT-014 | The formatter shall print each own-line comment, documentation comment and directive that precedes a using, member or top-level statement on its own line above it, in order, re-indented to the item's level (directives at column 0, `#region` and `#endregion` with the code), and shall keep one blank line where the author left one or more. | Must | Comments and directives above members, with and without blank lines. | `tests/golden/comments/leading-*` (M3) |
| FMT-015 | The formatter shall print a comment that follows the last token of a using, member or top-level statement on the same line after it, separated by one space. | Must | `int x;   // note` and `int y; /* note */`. | `tests/golden/comments/trailing-*` (M3) |
| FMT-016 | The formatter shall print the own-line comments and directives before a closing `}` and at the end of a file as the last lines of that body or file, including in an otherwise empty body. | Must | A comment before `}`, in an empty class, and at the end of the file. | `tests/golden/comments/closing-*` (M3) |
| FMT-017 | The formatter shall copy the text of disabled preprocessor branches unchanged, in place, from column 0. | Must | An `#if` branch with odd indentation. | `tests/golden/directives/disabled-*` (M3) |
| FMT-018 | The formatter shall never change the text of a comment (the first line of a multi-line comment is re-indented; its other lines are not touched). | Must | Comments with unusual inner whitespace and a multi-line block comment. | `tests/golden/comments/text-*` (M3) |
| FMT-020 | The formatter shall print a block as `{`, its statements one per line indented one level, and `}` on its own line, with an empty block as `{ }`, and shall print statements with the trivia rules of FMT-014 to FMT-016 (own-line comments and directives above a statement, a comment after it, closing lines before `}`). | Must | A method body with comments above, after and before `}` of its statements. | `tests/golden/statements/*` (M2) |
| FMT-021 | The formatter shall put the body of an `if`, `else`, `for`, `foreach`, `while`, `do`, `using`, `lock`, `try`, `catch` and `finally` on the next line, a block on its own lines at the statement's indent and any other statement indented one level, and shall keep `else if` on one line. | Must | An `if` / `else if` / `else` chain with block and non-block bodies. | `tests/golden/statements/if*` (M2) |
| FMT-022 | The formatter shall print the header of `if`, `while`, `for`, `foreach`, `switch`, `using`, `lock` and `catch` on one line when it fits in 100 columns and otherwise with the content of the parentheses on its own indented lines, breaking the outermost group first. | Must | A condition longer than 100 columns. | `tests/golden/statements/*` (M2) |
| FMT-023 | The formatter shall print a `switch` statement with its braces on their own lines, each section's labels on their own lines at the section's indent and the section's statements indented one level, and a `try` with each `catch` and `finally` on its own line. | Must | A switch with stacked labels, a block section and a default. | `tests/golden/statements/switch*`, `tests/golden/statements/try*` (M2) |
| FMT-024 | The formatter shall keep an expression on one line when it fits in 100 columns and otherwise break its outermost group first: argument lists one argument per line, binary and logical operators at the start of the continuation line, a conditional expression with `?` and `:` at the start of their lines, a lambda body after `=>` on its own line. | Must | Calls, operator chains, conditionals and lambdas that are too long. | `tests/golden/expressions/*` (M2) |
| FMT-025 | When a chain of member accesses and calls has more than two groups and does not fit on one line (or a group before the last contains a forced break), the formatter shall put each group after the first on its own line, indented one level, starting with `.`. | Must | A LINQ chain of four calls. | `tests/golden/expressions/chains*` (M2) |
| FMT-026 | When the last argument of a call is a lambda with a block body, an anonymous method, or an object, array or collection creation with an initializer, and the text before it fits on the line, the formatter shall open that argument on the call's line. | Must | `Run(() => { ... })`, `Add(a, new Foo { ... })`. | `tests/golden/expressions/lambda-arguments*` (M2) |
| FMT-027 | The formatter shall print object, array, collection and anonymous-object creation and initializers on one line when they fit and otherwise with the braces on their own lines and one element per line. | Must | An initializer that is too long, nested initializers. | `tests/golden/expressions/creation*`, `initializers*` (M2) |
| FMT-028 | When a declarator, assignment, field, property initializer or return has a value that is a binary or logical expression, the formatter shall keep it on the line when it fits and otherwise break after `=` and wrap the operators; any other value stays on the line of `=` and breaks inside itself. | Must | A long condition assigned to a local, a long call assigned to a field. | `tests/golden/expressions/assignments*` (M2) |
| FMT-029 | When a statement or an expression has no printer, or a comment or directive is inside it in a position FMT-009 does not format, the formatter shall copy that statement or expression as written and shall keep formatting its neighbours; the unit is never larger than a statement, and a copied child that ends in a `//` comment is never followed by more code on its line. | Must | A `goto` between formatted statements; a comment inside an argument list. | `tests/golden/statements/comments*`, `FormatterTests.AStatementWithACommentInsideIsVerbatimAndItsNeighboursAreFormatted`, `FormatterTests.AnExpressionWithNoPrinterIsVerbatimInsideAFormattedStatement` (M2) |
| FMT-030 | The formatter shall not add or remove a token: braces, parentheses and trailing commas are kept as written, and an initializer that has a trailing comma shall be printed with one element per line. | Must | An initializer with and without a trailing comma. | `tests/golden/expressions/initializers*`, the tree-equivalence invariant (M2) |

## Configuration (CFG)

Supported keys, values and the rules for everything else are decided in
[ADR 0012](../decisions/0012-read-editorconfig-with-a-small-parser-in-core.md).

| ID | Requirement | Priority | Scenario | Test anchor (planned) |
|---|---|---|---|---|
| CFG-001 | Where `.editorconfig` sets `indent_style` (`space` or `tab`) and `indent_size` (a number, or `tab`) or `tab_width`, the formatter shall indent each level by that many columns, using tabs (and spaces for a remainder smaller than `tab_width`) for `tab`, and shall count a tab as `tab_width` columns for the line width. | Must | Same input, two configs; a width boundary under tabs. | `ConfigGoldenTests` fixtures `golden/config/indent-*` (M4), `DocPrinterTests.ATabCountsAsTheTabWidthWhenFitting` (M4) |
| CFG-002 | The formatter shall resolve `.editorconfig` files nearest first, stop at a file whose preamble sets `root = true`, apply the matching sections of each file in file order, and let a nearer file override a farther one. | Must | Nested config directories. | `EditorConfigResolverTests.ResolutionOrder`, `EditorConfigResolverTests.StopsAtRoot` (M4) |
| CFG-003 | If `.editorconfig` contains a key the formatter does not support, then the formatter shall ignore it without failing. | Should | Config with unknown key. | `EditorConfigResolverTests.UnknownKeysAreIgnored` (M4) |
| CFG-004 | The formatter shall match a section name to a file path as the [EditorConfig specification](https://spec.editorconfig.org/) defines: `*`, `**`, `?`, `[seq]`, `[!seq]`, `{a,b}`, `{n..m}`, backslash escapes, and a name with a slash relative to the `.editorconfig`'s directory while a name without one matches at any depth. | Must | A table of patterns and paths. | `GlobTests` (M4) |
| CFG-005 | The formatter shall read keys and the values of supported keys case-insensitively, take the last assignment in precedence order, and treat the value `unset` as removing the key's earlier assignments. | Must | `Indent_Style = TAB`; `indent_size = unset` in a nearer file. | `EditorConfigResolverTests.KeysAndValuesAreCaseInsensitive`, `EditorConfigResolverTests.UnsetRemovesAValue` (M4) |
| CFG-006 | Where `.editorconfig` sets `max_line_length` to a number, or to `off`, the formatter shall wrap at that width, or never wrap for `off`; otherwise the width is 100. | Must | Same input at widths 60 and 120. | `FormatterOptionsTests.MaxLineLengthSetsTheWidth`, `ConfigGoldenTests` fixtures `golden/config/width-*` (M4) |
| CFG-007 | Where `.editorconfig` sets `end_of_line` to `lf` or `crlf`, the formatter shall write that line terminator for every line break it writes and in every comment, directive and disabled-text line, and shall leave the text inside a token (such as a multi-line string literal) as written; `cr` is not supported (CFG-010). | Must | A file with mixed endings and a verbatim string. | `FormatterOptionsTests.EndOfLineIsAppliedToCopiedTextCommentsAndDirectives`, `FormatterOptionsTests.EndOfLineIsNeverAppliedInsideATokenButTheCodeAroundItIs` (M4) |
| CFG-008 | Where `.editorconfig` sets `insert_final_newline = false`, the formatter shall end a non-empty file without a line terminator; otherwise it ends with exactly one (FMT-013). | Must | A file with and without a final newline under each value. | `FormatterOptionsTests.InsertFinalNewlineFalseEndsWithoutALineBreak` (M4) |
| CFG-009 | Where `.editorconfig` sets `charset` to `utf-8` or `utf-8-bom`, the formatter shall write a non-empty file without or with a UTF-8 byte order mark; where it is unset the file's own BOM is kept. | Should | A file with and without a BOM under each value. | `CliConfigTests.CharsetUtf8RemovesTheBom`, `CliConfigTests.CharsetUtf8BomAddsTheBom` (M4) |
| CFG-010 | If a supported key has a value the formatter cannot use (not a number, out of range, an unknown word, `end_of_line = cr`, a `charset` other than the two supported), then the formatter shall ignore that assignment, print one warning naming the file and line on stderr, and not change the exit code. | Must | A config with `indent_size = abc`. | `EditorConfigResolverTests.InvalidValuesWarn`, `CliConfigTests.AnInvalidValueWarnsAndKeepsTheExitCode` (M4) |
| CFG-011 | If an `.editorconfig` file cannot be read, then the formatter shall print one warning on stderr, treat the file as absent, and format the files as usual. | Must | An unreadable `.editorconfig`. | `EditorConfigResolverTests.AnUnreadableFileIsSkippedWithAWarning`, `CliConfigTests.AnUnreadableEditorConfigDoesNotStopTheRun` (M4) |
| CFG-012 | The formatter shall read and parse each `.editorconfig` file at most once per run, however many files it formats. | Should | Count reads over 1,000 files. | `EditorConfigResolverTests.EachFileIsReadOnce` (M4) |
| CFG-013 | The formatter shall keep the invariants FMT-001 to FMT-003 and FMT-005 under every supported combination of keys. | Must | Every golden input under tabs, 2 spaces, widths 60 and 120, CRLF, LF and no final newline; the corpus under its own `.editorconfig` files. | `OptionMatrixTests`, `CommentMutationTests.FormattingMutatedFilesKeepsEveryInvariantUnderOtherSettings`, `CorpusEditorConfigTests` (M4) |

## Command line (CLI)

| ID | Requirement | Priority | Scenario | Test anchor (planned) |
|---|---|---|---|---|
| CLI-001 | When `--check` is set, the formatter shall write no files and exit 1 if any file would change. | Must | Unformatted file with `--check`. | `Cli.CheckExitsOneWithoutWriting` (M6) |
| CLI-002 | When `--stdin` is set, the formatter shall read source from stdin and write the result to stdout. | Must | Pipe a buffer. | `Cli.StdinToStdout` (M6) |
| CLI-003 | If an error occurs for an input, then the formatter shall exit 2 and modify nothing for that input. | Must | Unreadable path, parse error. | `CliFormatTests.ParseErrorLeavesFileUntouched`, `CliFormatTests.AMissingPathIsAnError` (M1) |
| CLI-004 | The formatter shall not require an MSBuild project, solution or restore to run. | Must | Format a folder of loose `.cs` files. | `CliFormatTests.NoProjectNeeded` (M1) |
| CLI-005 | The formatter shall write each changed file atomically, so an interrupted or failed run never leaves a partly written file. | Must | Fail the write of the second of two files. | `CliFormatTests.WritesAreAtomic` (M1) |
| CLI-006 | The formatter shall format each `.cs` file named on the command line and every `.cs` file under each named directory. | Must | A folder tree with `.cs` and other files. | `CliFormatTests.DiscoversCSharpFiles` (M1) |
